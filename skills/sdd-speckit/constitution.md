# Constitution (공통 원칙)

`/sdd-speckit-*` 모든 단계가 지키는 원칙이다. 프로젝트 `CLAUDE.md`의 서비스 요구사항과 스택 파일의 규칙도 이 constitution에 포함된다(우선순위: `CLAUDE.md` > 스택 파일 > 이 파일). 각 원칙의 MUST를 어기면 analyze·converge에서 CRITICAL이다.

## 핵심 원칙 (Core Principles)

### I. spec 먼저
- MUST: spec 없이 구현하지 않는다. spec·plan에 없는 상황은 추측하지 않고 묻는다.
- MUST: 동작이 바뀌면 spec을 먼저 고친다. 코드와 문서가 어긋난 채로 머지하지 않는다.

### II. 레이어와 스택 규칙
- MUST: 스택 연결 값의 **레이어** 규칙을 지킨다(레이어 건너뛰기, 역방향 import 금지).
- MUST: 외부 시스템과 DB는 정해진 래퍼·repository를 통해서만 접근한다.

### III. 비즈니스 규칙마다 테스트
- MUST: spec의 비즈니스 규칙(쿼터, 소유권, 상태 전이 등)과 에러 케이스마다 정상/에러 테스트가 하나 이상 있다. upstream과 달리 테스트는 선택이 아니다.
- MUST: 외부 시스템·DB는 가짜 객체로 대체해 테스트한다.

### IV. 정해진 에러 표현
- MUST: 비즈니스 에러는 스택 연결 값의 **에러 표현**(식별자 + 상태 코드)으로만 낸다. 허용 상태 코드는 `CLAUDE.md`를 따른다.
- MUST: 모든 에러 케이스는 contracts의 에러 표에 식별자와 상태 코드가 있다.

### V. 단순함
- SHOULD: 지금 필요한 것만 만든다. 추상화·새 의존성·새 컴포넌트는 plan의 복잡도 기록에 이유와 버린 대안을 적는다.
- MUST: 되돌리기 어려운 결정(데이터 구조, 공개 API 형태)은 plan에 근거를 남긴다.

### VI. 작게 진행하고 확인받기
- MUST: 작업 하나 = 커밋 하나. 작업마다 멈추고 사람의 확인을 받은 뒤 커밋한다.
- MUST: 커밋 전에 스택 연결 값의 **확인 명령**(lint·format·테스트)이 통과한다.

## 운영 (Governance)
- 이 파일은 툴킷 공통이다. 바꾸려면 툴킷 PR로 한다. 프로젝트에만 맞는 원칙은 `CLAUDE.md` 서비스 요구사항에 둔다.
- plan의 Constitution Check는 위 원칙과 `CLAUDE.md` 요구사항 중 이 기능에 걸리는 것만 적는다.
