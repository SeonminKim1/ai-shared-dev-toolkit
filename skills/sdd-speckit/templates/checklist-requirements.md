# spec 품질 체크리스트: <기능 이름>

- **목적**: plan으로 넘어가기 전에 spec의 완성도 확인
- **작성일**: YYYY-MM-DD
- **대상**: [spec.md](../spec.md)

## 내용 품질 (Content Quality)
- [ ] 구현 디테일(언어, 프레임워크, Method/Path, 필드 타입, 상태 코드)이 없다
- [ ] 사용자 가치와 비즈니스 규칙에 집중한다
- [ ] 필수 섹션(개요, 유저 시나리오, 요구사항, 성공 기준)이 모두 채워졌다
- [ ] 범위 제외가 비어 있지 않다

## 요구사항 완성도 (Requirement Completeness)
- [ ] `[NEEDS CLARIFICATION]` 표시가 남아 있지 않다
- [ ] 요구사항이 테스트 가능하고 모호하지 않다
- [ ] 성공 기준이 측정 가능하고 기술과 무관하다
- [ ] 모든 유저 스토리에 인수 시나리오가 있다
- [ ] 엣지 케이스(경계값, 권한, 동시성, 외부 실패, 상태 전이, 스택 연결 값의 엣지 케이스)가 식별됐다
- [ ] 의존성과 가정이 적혀 있다
- [ ] `CLAUDE.md` 서비스 요구사항과 충돌하지 않고, 서비스 전체 규칙이 섞여 있지 않다

## 기능 준비도 (Feature Readiness)
- [ ] 모든 기능 요구사항에 인수 기준이 있다
- [ ] 유저 시나리오가 주요 흐름을 다룬다
- [ ] 완료 기준과 성공 기준이 서로 맞다

## 메모
- 체크되지 않은 항목은 clarify·plan 전에 spec을 고친다.
