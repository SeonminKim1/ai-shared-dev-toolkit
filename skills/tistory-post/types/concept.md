# A. 개념 정리
카테고리: 개념 정리 / 개발 지식 정리, DB 지식, 개발 인사이트

## 기본형
- h2 3~6개. 번호형(`1. 용어 정의`, `1. 배경 및 문제 상황`으로 시작하는 경우 많음)과 비번호형(`개요` → `X 란` → `X 구성` → `결론`, `A vs B vs C`) 둘 다 쓴다.
- 번호형은 마지막을 번호 없는 `참고 문서`(링크 ul)로 끝낸다 (링크 없으면 생략). 비번호 h2 아래 하위 단계는 h4 `1. ~`.
- h2 바로 아래 1~2줄 리드로 섹션을 요약한다. 예: "사용자가 대금을 지불하는 도구에 따라 기술적 과제가 상이함."
- 소주제는 `<b>1) 소주제</b>` + ul. ul 항목은 `<b>키워드 :</b> 설명 (예시: 구체적 상황)`. 용어 정의는 `정의 : …` / `특징 : …` 두 줄.
- 실무형 항목: `원인 :` / `진단 :` / `결과 :`, `장애 시나리오 예시` (설정값 → 결과 → 에러)
- 결론은 굵은 한 줄로 못 박는다: `<b>따라서 A가 B보다 무조건 작게 설계를 맞춰야 안전</b>`
- 비교는 **표**를 적극 쓴다 (구조/설명/장점/단점). 끝에 `비교 : 어떤 것이 좋을까` → `최종 결론`을 둘 수 있다.

## 변형
- **설계 기준** ([좋은 DB 설계하기] 수치형 필드): `개요` 한 줄 → `기준` h2 아래 `<b>케이스</b>` + ul(타입, 범위, 조건, `ex) 예시`) 반복. 아주 짧다.
- **견해** ([코드 리뷰]에 대한 견해): 도입 2~3줄(계기, 읽은 글 링크) → 주장 문장 h2 (`코드는 타이밍이다.`) → `<b>개요</b>` + ul, `<b>생각</b>` + ul.
- **경험 정리** ([SW 개발] 애자일 경험 정리): h2 없이 `경험했던 X에 대해 정리` 한 줄 → 번호 h2마다 ul만 (리드 없이). `소요 시간: 약 1시간`, `A >> B >> C`, `=> 이 이상이면 백로그 급` 같은 실무 판단.
- **선택지 비교** ([좋은 API 설계하기] 쿼리 파라미터): h2 1~3개. `<b>1) 선택지</b>` + ul(`ex) ?filter=1`, 장단점) 반복 → `<b>결론 :</b> 1을 조금 더 선호` 한 줄. 사례는 `<b>사례 1) 상황</b>` + ul.
- **선택 기준 비교** (Reflex vs Streamlit, ASGI 서버 비교): 결론을 앞에 둘 수 있다 (`<b>FastAPI 배포</b> → Uvicorn`). 후보마다 h2 → `<b>정의</b>` / `<b>특징</b>` ul. 기준 비교는 `<b>1. 기준</b>` + ul, 끝 항목 `<b>결론 : A > B</b>`(`=`, `>>`) → `최종 결론`에 실제 선택 + 소회 1~2줄.
- **연재 개념** ([디자인패턴] 행동 패턴 - 전략 패턴): 첫 h2는 상위 분류 소개 1줄 + 연재 목록 ul, 이번 글만 `<b>전략(Strategy) <- 이번 글에서 다룰 내용</b>` (연재 내내 같은 문구) → `X 란` → `등장 배경` → `구조`(역할별 `<b>Context</b>` + ul, 다이어그램 이미지 자리) → (예시 코드) → `장단점` → `다른 패턴과의 관계`(`<b>vs 상태 (State)</b>` + ul).
