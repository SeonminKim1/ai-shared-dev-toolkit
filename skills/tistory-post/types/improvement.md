# D. 개선기·적용기
카테고리: 회고 & 기록 / 프로젝트 경험기 또는 기타 경험 & 트러블슈팅, 주제에 따라 개념 정리 / DB 지식
예: [AWS Lambda] Python 3.12 전환과 배포 환경 개선기, [ORM] 협업 환경에서 db migration 기준 맞추기

## 기본형
- `개요`(또는 `1. 배경`) → `기존 구조의 한계` → `변경된 구조`(또는 `2. 진행`) → `변경된 구조 (표)` → `결과` / `기타 트러블 슈팅 및 이슈`
- `개요`는 반말 평서체(~였다, ~하기로 하였다), 진행 목적은 ol (`<b>비즈니스 로직은 수정 X</b> -> 이유`).
- 기존/변경 구조: `<b>기존 배포 환경</b>` + ol(단계) → `<b>요약 및 문제점</b>` + ul ("`2. 에서` …"처럼 ol 번호 참조). 흐름은 `A(x86_64) → B → C`.
- 전후 비교 표: 헤더 `(빈칸) | 변경 전 | 변경 후 | 특징, 개선`, 변경 없는 행은 `변경 없음`.
- 이슈: `<b>1. 이슈 제목</b>` + ul (상황 → `원인 :` → 해결) + 코드, `<b>해결 : …</b>`.
- ex) 예시에 실제 값을 넣는다 (`fastapi-layer : 13 | pydantic-layer : 44 <- 서비스 에러 발생`).

## 변형
- **리팩토링** ([리팩토링] 공통 코드 줄이기 / 함수명 개선): `배경`(연재 공통 문단 + 이번 주제 굵게 1줄) → `사례 N - 주제` h2마다 `<b>변경 전 코드</b>` → `<b>문제점</b>` ul → `<b>변경 후 코드</b>` → `<b>결론</b>` ul → 마지막 `결론` ul 3줄 (전 → 문제 → 후).
- **설계안 비교** ([기타] 임시 저장 서비스 경험기): `개요`(무엇을 고민했는지, 결론 굵게 미리 가능) → `요구 사항` ul(핵심은 `<b>중요 :</b>`) → `설계안` h2에 `<b>1안. 이름</b>` + 한 줄씩 → 안마다 h2 (`API 설계 - 1안`) + 번호 항목(장단, 영향) → `후기`(`<b>배경</b>` 선택 이유, `<b>후기</b>` 번호 ul로 아쉬움·다음엔).
